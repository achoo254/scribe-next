# Codebase Summary — Scribe

Tổng quan kiến trúc + module chính. Cập nhật 2026-10-19 ("Key riêng": key API của người dùng cho ElevenLabs, OpenAI, Gemini, Claude; model chữ của server chọn được nhà cung cấp; bỏ app desktop; đăng nhập chuyển sang hoandat-auth; prod ở `scribe.hoandat.com`; giao diện web theo khung Localman; gói "Sau cuộc họp": biên bản, dấu mốc, gửi sang chat; gói "Kho bản ghi": tìm kiếm toàn văn và hỏi đáp có trích mốc giây; gói free 200 MB / 7 ngày, xoá nhanh có hoàn tác, "Xoá tất cả", tải tệp lên để chép lời; dịch lời chép Việt ↔ Anh).

Scribe = app ghi/cắt/transcribe media trong hệ sinh thái hoandat. Repo có **2 ứng dụng**:

| App | Vị trí | Stack | Vai trò |
|-----|--------|-------|---------|
| **Web** | `web/` + `server/scribe-be/` + `crates/core-split/` | React 19 + Vite 7 + Tailwind 4 (token từ localman-next) · BE Rust/axum (musl static) · MongoDB · đăng nhập hoandat-auth (OIDC) | Ghi (browser) + cắt file + **chép lời bằng OpenAI** (key của server, đo phút theo user, quota tháng + trần chi phí; chỉ email trong `TRANSCRIBE_EMAILS` tới khi bật `TRANSCRIBE_OPEN`) |
| **iPhone** | `web/ios/` (Capacitor 8, đóng gói bản build của `web/`) | Swift plugin + cùng mã React | Ghi nền khi khoá màn hình theo đoạn 1 phút, lưu bền, tự tải lên; dùng chung backend web. Chi tiết: [ios-app.md](./ios-app.md) |

## Web app — Frontend (`web/`)

React 19 + Vite 7 + Tailwind 4 + TanStack Query + Radix. Token màu lấy từ localman-next (`styles/tokens.css`, kiểm tương phản bằng `pnpm run check:tokens`).

- **Router** (`routes.tsx`, `createBrowserRouter`): `/` → `/record`, `/record`, `/split`, `/transcripts`, `/transcripts/:key` (khoá phiên qua `transcriptPath()` ở `layout/app-paths.ts`; `?t=<giây>` nhảy tới câu và phát từ giây đó), `/search?q=` (`searchPath()`), `/privacy`, `/terms` (công khai: khách xem trong `layout/public-layout.tsx`, người đã đăng nhập xem trong shell nên mở khi đang ghi không mất phiên ghi; route có `handle: PUBLIC_ROUTE`, `RequireAuth` nhận `guest`), `/login`, `/__ui` (chỉ dev). Các trang `/transcripts*` và `/search` chỉ có khi `me.canTranscribe`. Trạng thái ghi (`pages/record/record-state.tsx`) và upload/job Cắt file (`pages/split/split-state.tsx`) nằm trong `layout/signed-in-state.tsx`, dưới `RequireAuth`: đổi trang không mất phiên ghi, đăng xuất thì unmount. `PageError` là `errorElement` bên dưới shell, trang lỗi không làm mất trạng thái đó. ## Web app — Backend (`server/scribe-be/`)

Rust/axum → **1 static musl binary**, bind `127.0.0.1:8787`, cấu hình nhúng compile-time (`build.rs`/`option_env!`), bí mật (session key, secret OIDC, key OpenAI, token bot) đọc từ tệp lúc khởi động, TLS out-bound = rustls (musl sạch).

**Modules** (`src/`):
- `main.rs` — bootstrap (hoặc nhánh CLI `admin`): connect Mongo, tạo index (index của `transcript_sentences`, kể cả text index, tạo đồng bộ; lỗi thì dừng khởi động vì `$text` lỗi khi chưa có text index), reset job kẹt, khởi `jobs::start_worker` + `retention::start_sweeper` + `search::index::start_backfill` + task long-poll `chat_link::poll` (chỉ khi bật `CHAT_LINK_POLL`), serve.
- `config.rs` — hằng dung lượng theo gói: free `FREE_QUOTA_BYTES=200MB`, `FREE_MAX_FILE_BYTES=200MB`, `FREE_RETENTION_DAYS=7`; plus `PLUS_QUOTA_BYTES=5GB`, `PLUS_MAX_FILE_BYTES=2GB`, `RETENTION_DAYS=14` (cũng là hạn mặc định cho doc cũ thiếu `expiresAt`). Áp qua `models/plan.rs` `Plan::storage()`; gói của user lấy bằng `user::effective_plan` (`plan::effective`, plus hết hạn thì về free). Biến build (bắt buộc / mặc định), allowlist, hạn mức chép lời.
- `auth.rs` — đăng nhập hoandat-auth. Web: BFF, client confidential `scribe-web`, Code + PKCE phía server (`state`/`nonce`/verifier ở `auth_states`), back-channel logout. iPhone: client public `scribe-mobile`, app gửi code + verifier + nonce tới `/api/auth/native/exchange`, nhận token thiết bị để `/api/auth/native/refresh`. Email chưa xác minh / ngoài allowlist / tài khoản bị khoá → từ chối; user cũ thời Firebase ghép theo email. Cookie phiên `__Host-scribe` (https) HttpOnly+SameSite=Lax; middleware `require_auth` (cache phiên 30 giây).
- `oidc.rs` — discovery, JWKS, xác minh ID token và logout token, đổi code, refresh; email/tên lấy từ `userinfo` (ID token chỉ có `sub`), `sub` hai nguồn phải khớp.
- `session.rs` — session key (tự sinh), token ngẫu nhiên, băm token, mã hoá refresh token IdP. `models/session.rs` — `sessions` (web 12 giờ trượt tới 7 ngày, mobile 12 giờ), `devices`, `auth_states`, `logout_jtis`.
- `upload.rs` — chunked upload (init/chunk/status/finalize) append-disk, quota và cỡ tệp theo gói (413 kèm câu cho người đọc), magic-byte (`infer`). Dùng cho cả Cắt file và "Tải tệp lên" ở trang Ghi âm: file `kind:upload` (lưu `durationS`, `hasVideo`). Chỉ lượt init gửi `purpose: "transcribe"` (trang Ghi âm; giá trị khác bị từ chối) cho file có `purpose: "transcribe"`: file đó hiện ở Lịch sử ghi và chép lời như bản ghi một file (khoá `f:<id>`, tên tệp không bao giờ bị coi là đoạn iPhone). Tệp Cắt file không có `purpose`, không vào Lịch sử ghi, không chép lời được, không bị "Xoá tất cả" xoá. Ngược lại, `GET /api/files/manage` (danh sách trang Cắt file, `file::list_split_files`) không liệt kê tệp có `purpose: "transcribe"`. Finalize (upload và bản ghi) không xét lại cỡ tệp theo gói: chunk đã chặn lúc nhận, gói hạ giữa chừng không làm mất phần đã nhận.
- `transcribe/` — chép lời bằng ElevenLabs Scribe v2 (mặc định, `TRANSCRIBE_PROVIDER`) hoặc OpenAI `gpt-4o-mini-transcribe` (dự phòng). ElevenLabs (`transcribe/whole.rs`, `elevenlabs.rs`, `words.rs`): một request cho cả tệp, hoặc cả phiên iPhone — `POST /api/transcripts` mở rộng một đoạn ra mọi đoạn của phiên, xếp chung một `runId`; worker gom các file cùng `runId`, ghép bằng ffmpeg `concat` (mốc đoạn sau = tổng thời lượng các đoạn trước), nén Opus, gửi `diarize=true`, `timestamps_granularity=word`, `tag_audio_events=false`, rồi chia từ về đoạn chứa mốc bắt đầu của nó và dựng câu từ timestamp từ (tách ở dấu câu, đổi người nói, ngừng ≥ 1,5 giây, ≤ 120 ký tự); câu có `speaker` (`s0`… theo thứ tự xuất hiện). Phiên còn đoạn đang tải lên thì hoãn 20 giây. Tên người nói ở `transcript_docs.speakers.names` (đặt lại nhãn mặc định khi lượt chép xong; `PATCH …/speakers` đổi tên); xuất TXT/MD/DOCX thêm "Tên: " ở chỗ đổi người nói, SRT mỗi cue, VTT `<v Tên>`; đầu vào biên bản có tên nhưng băm nguồn không gồm tên. Trần giờ ElevenLabs mỗi tháng (`ELEVENLABS_MONTHLY_HOURS`, sổ `el:<tháng>`) giữ chỗ trước khi gửi; ElevenLabs hết credit ⟹ dấu `el_exhausted:<tháng>` chặn tới tháng sau (gỡ: `admin elevenlabs-quota --clear`), key hỏng ⟹ cờ ngắt như OpenAI. Luồng OpenAI: `POST/GET /api/transcripts`, `GET /api/transcripts/export` (`format=txt|srt|vtt|md|docx`, ghép cả phiên iPhone, câu đã sửa; `transcribe/export.rs`: md/docx là tài liệu cuộc họp — tiêu đề, giờ và thời lượng, biên bản, dấu mốc, lời chép `[mm:ss]` — chỉ kèm biên bản/dấu mốc khi mọi file cùng một phiên; docx tạo bằng crate `docx-rs` (MIT, tắt tính năng `image`, thêm ~1,4 MB vào binary musl), phông Arial; tên tệp theo tiêu đề, `filename*` UTF-8); hàng đợi riêng trong collection `transcripts`; cắt mảnh ≤45 giây tại khoảng lặng (ffmpeg `silencedetect`), nén Opus, gọi song song 4 mảnh; mảnh hoàn toàn im lặng (đỉnh < −30 dB theo `volumedetect` lúc nén) không gửi, không tính phút. Key OpenAI của server đọc từ tệp lúc khởi động (`Transcriber`, có cờ ngắt khi key hỏng). Tiền: `POST /api/transcripts` giữ chỗ phút trong `models/usage.rs` (user → quỹ free → trần tổng, `$inc` có điều kiện, không cần transaction) rồi xếp hàng; worker cộng `sentS` trước mỗi lần gửi audio; lượt kết thúc (xong, lỗi, xoá) đóng sổ đúng một lần theo `runId` và quyết toán `sentS − chargedS`, ghi `transcribe_runs` để đối soát. Restart: lượt dở chạy lại, cắt ngang lần hai thì dừng. Gói free còn giới hạn ngày mỗi tài khoản (không giới hạn theo IP); thời gian chờ của tài khoản mới mặc định 0 (bỏ ngày 19/10/2026, `TRANSCRIBE_FREE_DELAY_HOURS` vẫn đặt lại được). `admin.rs` — CLI `scribe-be admin set-plan|usage|elevenlabs-quota|block|unblock|notify-test|shorten-free-retention` (`usage` in thêm sổ giờ ElevenLabs) (`shorten-free-retention` đếm, `--apply` mới ghi, tệp của user không có gói plus hiệu lực về `expiresAt = min(expiresAt, createdAt + 7 ngày)`; `block` gỡ luôn liên kết chat; `usage --recompute` cộng cả chi phí tóm tắt và hỏi đáp từ `summary_runs`, `ask_runs`). `notify.rs` — báo chủ sản phẩm qua bot chat.hoandat.com. `transcribe/docs.rs` — transcript theo phiên ghi (`/api/transcript-docs`, xem bảng API): gom đoạn bằng `file::session_key` (`s:<sessionId>` cho phiên iPhone, `f:<fileId>` cho bản ghi một file và tệp tải lên; file chép lời được = file của Lịch sử ghi: `FileDoc::in_history` / `file::history_filter()` = `kind:recording` hoặc `kind:upload` có `purpose:"transcribe"`), ghép kết quả máy với tiêu đề + câu sửa lúc đọc. Câu sửa gắn `runId` của lượt chép: chép lại thì phần sửa của đoạn đó tự hết hiệu lực; PUT ghi có điều kiện, chen lượt chép lại → 409. `realtime.rs` — chép trực tiếp trên iPhone, nhà cung cấp theo `REALTIME_PROVIDER`: ElevenLabs Scribe v2 Realtime (mặc định; `POST /v1/single-use-token/realtime_scribe` bằng key ElevenLabs của server, token dùng một lần hạn 15 phút; phản hồi kèm `url` WebSocket có sẵn cấu hình `scribe_v2_realtime`, `pcm_24000`, `vi`, VAD 1,0 giây, `include_timestamps`) hoặc OpenAI Realtime (`POST /v1/realtime/client_secrets`, phiên `transcription`, `gpt-4o-mini-transcribe`, `server_vad` 500 ms, hạn 600 giây); key không rời server. Chỉ email trong `REALTIME_EMAILS`. Tính phút chung sổ với chép lời cả file (hạn mức gói, sổ ngày và quỹ free, trần tổng, cờ tạm ngưng khi key hỏng); sổ quy theo USD giữ số giây quy đổi theo giá realtime (`usage::reserve_priced`, `costRatio`), qua ElevenLabs còn giữ chỗ trên sổ giờ `el:<tháng>` (`elRatio` = 0,39/0,22; đầy ⟹ `PROVIDER_HOURS`; 402 hoặc app báo `quotaExceeded` ⟹ dấu hết quota tháng). Mỗi token giữ chỗ trước, app báo số giây thật khi đổi token hoặc dừng ghi, quyết toán theo `realtime_tokens.settled` (một lần) trên mọi sổ và ghi `transcribe_runs` (`kind: "realtime"`, `costS`, `elS`); không báo thì phần giữ chỗ tính trọn. Audit `realtime.token`, `realtime.blocked`, `realtime.provider_quota`. `transcribe/bookmarks.rs` — dấu mốc bấm lúc đang ghi: doc tạo lười bằng upsert vì lúc đó phiên có thể chưa có file; quyền sở hữu kiểm theo trạng thái phiên (giải thích ở đầu tệp). `POST /api/recordings/init` trả `fileId` giữ trước để web có khoá `f:<fileId>` ngay khi ghi.
- `account.rs` — xoá tài khoản `POST /api/me/delete` (app dùng; `DELETE /api/me` cũng nhận), body `{confirm: "XOÁ"}` so sau chuẩn hoá: 409 `RECORDING_OPEN` khi đang ghi trên trình duyệt (`recordings::recording_live`); rồi `users.deletingAt` + `deleted_users` (TTL 7 ngày) — từ đây đăng nhập web/iPhone bị từ chối (`login?error=deleting`) và làm tiếp việc xoá, middleware phiên và worker coi tài khoản như không còn; phần còn lại chạy trong task riêng (ngắt kết nối không dừng; lỗi trả 200 `complete: false`): thu hồi grant IdP của mọi thiết bị (lỗi thì giữ bản mã hoá để vòng retention thử lại, id thiết bị giữ để `native/refresh` trả 410 `ACCOUNT_DELETED` và app xoá đoạn còn trên máy), xoá phiên và bỏ khỏi cache, rồi `purge_user`: tệp qua `file::delete_doc` (chỉ tệp trong `{data_dir}/<userId>/`), mọi collection theo `userId`, sổ riêng theo tiền tố `_id`, thư mục của user, cuối cùng doc `users`; `*_runs` và `realtime_tokens` giữ số tiền với `userId: "deleted"`; audit giữ tới TTL nhưng bỏ `name`/`email`/`title`/`chatId`/`error`. Danh sách và lý do ở đầu tệp.
- `user_keys/` — "Key riêng" (giải thích ở đầu `mod.rs`): `crypto.rs` AES-256-GCM, bí mật 32 byte từ tệp `USER_KEYS_SECRET_PATH` (quyền 600, thiếu/sai ⟹ tính năng tắt), nonce 96 bit ngẫu nhiên mỗi lần mã hoá, AAD = userId + nhà cung cấp, bản rõ trong `Zeroizing`; `store.rs` collection `user_keys` (`{userId, provider}` unique, bản mã, nonce, `last4`, `status` valid|invalid|quota|unreadable, giờ tạo/sửa/kiểm) và `user_key_prefs`; `check.rs` kiểm key lúc lưu bằng một lần gọi không tốn credit (ElevenLabs cấp token realtime dùng một lần — chạy được với key chỉ có quyền Speech to Text; OpenAI/Anthropic `GET /v1/models`; Gemini `GET /v1beta/models`); `api.rs` các route `/api/me/keys…`. Chọn key cho từng việc (`pick`): nhà cung cấp người dùng chọn nếu key hợp lệ, không thì key hợp lệ đầu tiên, không có thì key server với hạn mức thường. Lượt chép xếp hàng chỉ ghi `byok: <nhà cung cấp>`; worker đọc và giải mã key của chủ phiên lúc chạy. Key riêng lỗi lúc dùng ⟹ lượt dừng với "Key … của bạn không dùng được: … — sửa hoặc xoá key ở Key riêng", key bị đánh dấu, không chuyển sang key server, không đụng cờ ngắt hay dấu hết quota của server. Việc chạy bằng key riêng không giữ chỗ/không tính sổ nào (vẫn ghi `transcribe_runs`/`*_runs` có `byok` và sổ xem `b:<userId>:<tháng>`). Chép lời bằng key riêng: ElevenLabs (cả phiên, người nói) như key server; OpenAI `gpt-transcribe` (`languages[]=vi`, theo mảnh); Gemini (`transcribe/gemini.rs`, mỗi mảnh ≤45 giây gửi kèm, JSON câu + giây ước lượng). Chép trực tiếp bằng key riêng: token ElevenLabs hoặc OpenAI cấp bằng key đó, không giữ chỗ.
- `summary/` — biên bản (tóm tắt, quyết định, việc cần làm, mỗi mục kèm giây) bằng OpenAI `SUMMARY_MODEL` (mặc định `gpt-4.1-mini`), chỉ khi người dùng bấm "Tóm tắt". Đầu vào là chữ đã áp câu sửa; lưu kèm băm đầu vào nên API báo `stale` khi chữ đổi. Tiền: lượt mỗi ngày theo gói + trần chi phí tháng mỗi tài khoản (sổ `summary_usage`), chi phí token quy ra giây chép lời tương đương và cộng vào trần tổng tháng của chép lời; phần có tiền chạy trong task riêng nên client ngắt kết nối không để sổ treo. Key hỏng chỉ tạm ngưng tóm tắt và hỏi đáp (cờ riêng, dùng chung), không ngắt chép lời. Lý do và quy tắc hoàn lượt ở đầu `summary/mod.rs`. `summary/meter.rs` — trình tự đo lường dùng chung cho tóm tắt và hỏi đáp (`models/summary.rs` `Feature::{Summary, Ask}`), thứ tự các bước ở đầu tệp. `summary/llm.rs` — lớp chuyển đổi model chữ dùng chung cho OpenAI (Chat Completions `json_schema` strict), Gemini (`generateContent`, `responseSchema` đổi từ JSON Schema sang tập con OpenAPI) và Anthropic (Messages `output_config.format`, tắt suy nghĩ ở Haiku 5.5); cùng trả nội dung theo schema + token vào/ra; bảng model ngắn và giá (`MODELS`). Model chữ của server chọn bằng `LLM_PROVIDER`/`LLM_MODEL` (mặc định OpenAI `gpt-4.1-mini`), chi phí quy ra trần theo giá model đó. `summary/share.rs` — gửi biên bản tới chat riêng đã liên kết (không bao giờ vào nhóm).
- `translate/` — dịch lời chép của một phiên sang `en`/`vi` khi người dùng bấm "Dịch". Câu dịch gắn câu nguồn theo `(fileId, chỉ số câu)` kèm băm chữ nguồn: chữ đổi thì câu là "bản dịch cũ"; một lượt chỉ gửi câu chưa dịch hoặc bản dịch cũ (dịch lại câu đã sửa, dịch tiếp sau lỗi), không còn câu nào thì không tính lượt. Đo lường qua `summary::meter` (`Feature::Translate`: lượt ngày riêng, chung trần tháng và trần tổng; giữ chỗ một lần cho mọi lô, quyết toán theo tổng token). `batch.rs` — lô ≤100 câu / 6.000 ký tự, JSON đánh số vào/ra, đầu ra phải khớp 1:1 số câu, lô lỗi thử lại một lần; các lô chạy tuần tự trong task nền, handler trả 202 sau khi giữ chỗ. Khởi động lại giữa lượt thì trạng thái báo `failed` ("bị ngắt"). Xuất có `lang` ở `GET /api/transcripts/export` (nhãn mục md/docx theo ngôn ngữ ở `export::Labels`, biên bản giữ ngôn ngữ gốc).
- `search/` — tìm kiếm toàn văn và hỏi đáp trên bản chép lời của chính người dùng. `index.rs` dựng index câu `transcript_sentences` từ đúng đường ghép của màn hình đọc (câu đã áp phần sửa, giây theo cả phiên), thay cả phiên mỗi lần dựng; khi nào dựng, khoá theo phiên, backfill một lần lúc khởi động và đối soát định kỳ giải thích ở đầu tệp. Xoá transcript hoặc file thì xoá câu đồng bộ trước, để câu đã xoá biến ngay khỏi tìm kiếm và hỏi đáp. `norm.rs` — chuẩn hoá (viết thường, bỏ dấu, đ thành d) và bỏ từ đệm tiếng Việt khỏi từ khoá câu hỏi. `mod.rs` — `GET /api/search`: một từ thì khớp tiền tố, nhiều từ thì `$text` rồi đòi khớp cả cụm, không có thì nới ra khớp đủ từ; ứng viên lấy từ phiên mới nhất trước, có trần. `ask.rs` — `POST /api/ask`: ngữ cảnh là nguyên bản ghi khi hỏi trong một bản ghi ngắn (mốc theo gói ở `full_context_chars`), còn lại là các câu liên quan nhất theo từ khoá kèm câu lân cận; model trích số dòng `[n]`, server đổi thành trích dẫn lấy từ chính ngữ cảnh. Không có câu liên quan thì trả "Không tìm thấy trong bản ghi." mà không gọi model và không tính lượt. Không lưu câu hỏi hay câu trả lời. Hằng số (trần ứng viên, số câu, rate limit) ở đầu từng tệp.
- `chat_link/` — liên kết tài khoản với chat riêng trên chat.hoandat.com, không thêm endpoint public: deep link `/start <token>` → bot hỏi xác nhận (email che bớt) → bấm "Xác nhận liên kết" mới gắn (`flow.rs`, lý do chống liên kết hộ ở đầu tệp); bot nhận `/unlink`. `poll.rs` — task long-poll `GET {NOTIFY_BOT_API}/updates`, offset lưu Mongo. **Chỉ một backend được poll:** dev và prod dùng chung token bot, mỗi bot chỉ có một poll (poll mới làm poll cũ nhận 409), nên `CHAT_LINK_POLL` mặc định tắt và chỉ bật trên prod; tắt thì `POST /api/chat/link` trả 503 `CHAT_LINK_DISABLED`. `bot.rs` — client Bot API.
- `idp_brand.rs` — tên tài khoản đăng nhập (tên hiển thị tenant của hoandat-auth): task nền hỏi `GET /internal/tenants/lookup?host=` của API nội bộ IdP (`IDP_INTERNAL_API_URL`, Basic `scribe` + tệp `IDP_INTERNAL_API_SECRET_PATH`) lúc khởi động rồi mỗi giờ, lỗi giữ tên cũ; mặc định `IDP_DISPLAY_NAME` (`Auth Next`); trả ở `GET /api/idp`. Web đọc một lần mỗi lần tải trang (`web/src/lib/idp-name.ts`, gọi từ `main.tsx`) và điền `{idpName}` vào mọi câu gọi tên tài khoản.
- `access_log.rs`, `audit.rs` — log mọi request + collection `audit_events` (TTL 180 ngày) cho hành vi người dùng.
- `recordings.rs` — quota và cỡ tệp theo gói; chunk làm vượt giới hạn bị cắt bỏ (413) nhưng phần đã nhận giữ nguyên, nên bản ghi finalize được tới lúc đầy (web tự dừng ghi; iPhone giữ đoạn trên máy và chờ). **Mode A streaming**: init/chunk/finalize open-ended cho MediaRecorder (mirror upload, coll `recording_sessions` riêng) → `files{kind:recording}`. Finalize **remux `-c copy -f webm`** để dựng Cues+Duration (webm MediaRecorder streaming thiếu → không tua được); remux lỗi → fallback rename giữ container gốc.
- `files.rs` — `GET /api/files` (lịch sử ghi: bản ghi + tệp tải lên ở trang Ghi âm theo `file::history_filter()`; mỗi file kèm `expiresAt` thật, web hiện "tự xoá sau N ngày" theo mốc này; `retentionDays` theo gói hiện tại chỉ cho câu giới thiệu) · `GET /api/files/:id` (stream + **HTTP Range** cho player tua) · `DELETE /api/files/:id` (xoá thủ công, ownership) · `DELETE /api/files` ("Xoá tất cả": đúng những file `GET /api/files` liệt kê, qua `file::delete_doc`; chừa file của phiên ghi đang mở, phiên iPhone có đoạn mới trong 10 phút qua và đầu vào job cắt đang chạy; tệp Cắt file không bị xoá; 3 lần/phút/user, audit `file.delete_all` kèm số đếm; đoạn cắt `output` không xoá) · `GET /api/me/usage` (dung lượng đã dùng, `quotaBytes`/`maxFileBytes`/`retentionDays`/`plan` theo gói).
- `jobs.rs` + `worker/split_worker.rs` — job queue cắt (claim atomic, concurrency=1). Mode B (upload webm): disk-free ≥2× → remux `-c copy -f matroska` → segment → dọn `fixed.mkv` → đoạn `kind:output` (tải zip). **Mode A (`recordingSplit`)**: input recording đã seekable → segment thẳng webm→webm + probe mỗi đoạn → đoạn `kind:recording` (vào Lịch sử ghi, phát/tua riêng) + **xoá bản ghi gốc**.
- `rate_limit.rs` — limiter in-memory theo real IP (`X-Real-IP` nginx-set): auth 120/60s, `/api/auth/native/exchange` 10/60s, protected 300/60s (miễn `/chunk`); ngân sách chung 45 lần/phút gọi token endpoint của IdP.
- `retention.rs` — sweep 1h: xoá file quá hạn (`expiresAt` tính lúc tạo theo gói của chủ file: free 7 ngày, plus 14 ngày; cả đoạn cắt) (**disk TRƯỚC → doc**, KHÔNG TTL native), dọn orphan `.part`/session/job cũ và `transcript_docs` không còn audio (doc chưa có biên bản được chừa 24 giờ để dấu mốc bấm trước khi có file không bị xoá), câu mồ côi trong index tìm kiếm (`sentence::delete_orphans`), rồi đối soát index (`search::index::reconcile`, bỏ qua khi chưa backfill xong), panic-isolation. `file::delete_doc(&FileDoc)` là nơi duy nhất xoá doc file: xoá kèm `transcripts`, câu sửa của đoạn và câu của file trong index tìm kiếm.
- `models/{file,job,user,session,plan,usage,transcript,transcript_doc,summary,chat_link,sentence}.rs`, `state.rs`, `error.rs`, `db.rs`, `routes.rs`.

**core-split** (`crates/core-split/`): `split_file` (ffmpeg segment `-c copy`), `remux_copy_to_mkv` (fix cues webm), `probe_file`/`size_cut_times`, `compute_segment_time`.

| POST | `/api/transcript-docs/{key}/summary` | tạo / tạo lại biên bản, trả đồng bộ; 409 `NOT_TRANSCRIBED`, 403 `SUMMARY_DAILY_LIMIT`/`SUMMARY_MONTHLY_LIMIT`/`CAP_REACHED` kèm `retryAt`, 503 khi tạm ngưng. `GET …/{key}` trả kèm `summary` (có `stale`) và `bookmarks` |
| POST | `/api/transcript-docs/{key}/translation` | `{lang}` (`en`\|`vi`): dịch câu chưa có bản dịch hoặc có bản dịch cũ; 202 `{lang, status:"running", done, total}`, không còn câu nào → 200 `status:"done"`, `total:0`, không tính lượt. 409 `NOT_TRANSCRIBED`, 403 `TRANSLATE_DAILY_LIMIT`/`TRANSLATE_MONTHLY_LIMIT`/`CAP_REACHED` kèm `retryAt`, 413 quá dài, 429 đang dịch hoặc bấm quá nhanh, 503 khi tạm ngưng. `GET …/{key}` trả kèm `translations: [{lang, status}]` |
| GET | `/api/transcript-docs/{key}/translation?lang=` · `…/translation/status?lang=` | bản dịch khớp từng câu của màn hình đọc `{status, done, total, error, outdated, missing, segments: [{fileId, sentences: [{text, outdated} \| null]}]}` (chưa có → `status:"none"`) / tiến độ không kèm câu |
| POST/DELETE | `/api/transcript-docs/{key}/bookmarks` · `…/bookmarks/{id}` | thêm dấu mốc `{at, label?}` (tối đa 200 mốc mỗi doc) / xoá |
| POST | `/api/transcript-docs/{key}/share` | gửi biên bản tới chat đã liên kết; 409 `CHAT_NOT_LINKED`, `CHAT_BLOCKED` (bot bị chặn → đã gỡ liên kết) |
| GET | `/api/me/keys` | Key riêng: `{available, keys: [{provider, last4, status, updatedAt, lastCheckedAt}], prefs, active, models}` — không bao giờ có key |
| PUT/DELETE | `/api/me/keys/{provider}` | `{key}` → kiểm với nhà cung cấp rồi lưu mã hoá, trả phần xem được (400 `KEY_FORMAT`/`KEY_REJECTED`/`KEY_NO_CREDIT`, 503 `KEY_CHECK_FAILED`/`USER_KEYS_DISABLED`, 429 quá 5 lần/phút) / xoá. `provider` = `elevenlabs`\|`openai`\|`gemini`\|`anthropic` |
| PUT | `/api/me/key-prefs` | `{transcribe?, live?, text?, textModel?}` chọn nhà cung cấp cho từng việc (`null` = tự chọn); trả như `GET /api/me/keys`. Mọi tính năng gặp key riêng không dùng được trả 403 `USER_KEY_FAILED` |
| GET/POST/DELETE | `/api/chat/link` | trạng thái `{linked, linkedAt, enabled}` / tạo deep link một lần (hạn 10 phút; 503 `CHAT_LINK_DISABLED`) / gỡ liên kết |

| GET | `/api/search?q=&limit=&key=` | tìm câu trong mọi bản ghi của mình (hoặc trong một bản ghi qua `key`); trả `{results: [{key, title, createdAt, fileId, at, text, before, after}], total}`; 429 khi tìm quá nhanh |
| POST | `/api/ask` | hỏi đáp `{question, key?}`, trả đồng bộ `{answer, citations: [{n, key, title, createdAt, at, text}]}`; 409 `NOT_TRANSCRIBED`, 403 `ASK_DAILY_LIMIT`/`ASK_MONTHLY_LIMIT`/`CAP_REACHED` kèm `retryAt`, 429 khi hỏi quá nhanh hoặc đang có một câu chạy, 503 khi tạm ngưng hoặc lỗi model |

Nhóm `/api/transcript-docs` và `/api/chat/link` có trần body 1 MiB; chỉ cần đăng nhập và đúng chủ dữ liệu. `/api/search` chỉ cần đăng nhập; `/api/ask` và `POST …/translation` cần quyền chép lời (đọc bản dịch chỉ cần đăng nhập). Hợp đồng chi tiết của hai route này nằm ở plan `dattqh/261016-2257-recording-library` (phase 1, mục "API cho web").

### MongoDB (database `$DB_NAME`)

`users` (`idpSub` unique; user cũ còn `firebaseUid`; `blocked`, `plan`/`planUntil`; `chat = {chatId, linkedAt}` khi đã liên kết chat) · `sessions` / `devices` / `auth_states` / `logout_jtis` (phiên thu hồi được) · `files` (kind `upload|output|recording`, `purpose:"transcribe"` ở tệp tải lên từ trang Ghi âm, `size`, `durationS`, `hasVideo`, `jobId`, `expiresAt` index thường) · `jobs` (queue cắt) · `upload_sessions` / `recording_sessions` (append-disk) · `transcripts` (kết quả máy + hàng đợi chép lời, `_id` = id file) · `transcript_docs` (`{userId, key}` unique, tạo đồng bộ lúc khởi động: `title`, `edits.<fileId> = {runId, texts}`, `summary` (biên bản + băm đầu vào), `bookmarks`) · `transcribe_usage` (sổ giây theo tháng giờ VN: `u:<userId>:<YYYY-MM>`, `free:<YYYY-MM>`, `all:<YYYY-MM>`; `chargedS`, `settled`, `sentS`, `reportBy`; `admin usage --recompute` cộng `chargedS` của token chưa quyết toán) · `transcribe_marks` (mốc quỹ/trần đã báo, đếm lần chạm giới hạn ngày) · `summary_usage` (lượt ngày tóm tắt `<userId>:<YYYY-MM-DD>`, lượt ngày hỏi đáp `ask:<userId>:<YYYY-MM-DD>`, lượt ngày dịch `tr:<userId>:<YYYY-MM-DD>`, chi phí tháng dùng chung `cost:<userId>:<YYYY-MM>`) · `summary_runs` / `ask_runs` / `translate_runs` (mỗi lượt gọi model — lượt dịch gồm mọi lô: mở trước khi gọi với `reservedS`, đóng khi quyết toán với token và `costS`; `ask_runs` không có câu hỏi hay câu trả lời) · `transcript_translations` (một doc mỗi `{userId, key, lang}` unique, tạo đồng bộ lúc khởi động: `status`/`done`/`total`/`error` của lượt gần nhất, `model`, `items.<fileId>.<chỉ số câu> = {h, t}` — `h` băm chữ nguồn lúc dịch; xoá bản chép lời xoá doc, xoá một đoạn gỡ `items.<fileId>`, retention xoá doc của phiên hết file) · `transcript_sentences` (index tìm kiếm, mỗi câu một doc `{userId, key, fileId, idx, at, text, norm, createdAt, gen, expiresAt}`; `gen` là thế hệ của lần dựng, `createdAt` là lúc bắt đầu phiên, `expiresAt` là hạn của file chứa câu; index `{userId, key, idx}`, `{userId, createdAt: -1}`, `{fileId}`, text index `userId_norm_text` trên `{userId, norm}` với `default_language: "none"`, TTL trên `expiresAt`;
